# GCSC School Management System

## Simple User Manual for the Sidebar and Hub Pages

This guide explains the menu shown on the left side of the system. It is written for office staff, teachers, accountants, and administrators who use the system every day.

## Before you start

- Your account may show fewer menu items or cards than another person. This is normal. The system only shows the areas your account is allowed to use.
- A **hub page** is a page that contains cards. Click a card to open the related work page.
- Usually, the safest order is: set up basic information first, enter daily information second, and review reports last.
- Use the correct academic session, class, section, and date before saving information.
- Check names, dates, amounts, and student IDs before pressing Save. Financial and student-history changes may affect reports.

## 1. Dashboard

### What it does

Dashboard is the system home page. It gives a quick view of the school today and links to common tasks.

### What you can see

- Quick actions such as marking attendance and adding a student.
- Total students and other student summary figures.
- Today’s attendance and attendance rate.
- Fee collection status and recent fee information.
- Class-by-class attendance.
- Attendance, fee, income, and expense trends.
- Student distribution by class.
- Upcoming student birthdays and recent exam information.

### How to use it

1. Open Dashboard after signing in.
2. Read the summary boxes to spot anything unusual.
3. Click a quick-action button when you want to do a common task.
4. Click a class, report, or linked item when you need to investigate a number.
5. Use the left menu to open the full work area.

The dashboard is a summary. For official records, always open the related module and check the detailed list or report.

## 2. Academics

### What it does

Academics builds the school structure used by students, attendance, exams, fees, and routines.

### Cards on the Academics hub

| Card | What it is for |
|---|---|
| Sessions | Create and manage academic years or sessions. |
| Classes | Add and arrange classes such as Class 1, Class 2, or Grade 8. |
| Sections | Create sections inside a class, such as A or B. |
| Groups | Create student groups used by the school. |
| Subjects | Add subjects and manage subject assignments. |
| Class Rooms | Keep the list of classrooms. |
| Class Routine | Prepare the class timetable for classes and teachers. |
| Time Schedule | Set teaching periods, break times, prayer time, and other time blocks used by routines. |

### Common workflow

1. Create the academic session.
2. Add classes and set their order.
3. Add sections for each class.
4. Add subjects and assign them as needed.
5. Add classrooms and set the time schedule.
6. Prepare the class routine.

### Important note

Time Schedule and Class Routine work together. Breaks, prayer time, and other non-teaching periods should be defined in the schedule, but only teaching periods should be selected for a lesson.

## 3. Admission Management

### What it does

This area manages a new applicant from the admission exam and application stage until the applicant becomes a student.

### Cards on the Admission Management hub

| Card | What it is for |
|---|---|
| Admission Exams | Create an admission exam, set the date and fee, and set total and pass marks for each class. |
| Applications | View and review submitted applications. Search by name, phone, birth certificate number, or class. |
| Admit Cards | Prepare and print admit cards for eligible or paid applicants. |
| Merit and Results | Enter admission marks and view passed or failed applicants. |
| Approved Students | See approved applicants and continue with admission. |
| Converted Admissions | See applicants who have already been changed into student records. |

### Typical admission process

1. Create or activate the admission exam.
2. Review incoming applications.
3. Confirm the application payment when required.
4. Generate and print the admit card.
5. Enter marks and review the result.
6. Approve the applicant.
7. Convert the approved applicant into a student.
8. Check the student in the Students area.

Do not convert an applicant twice. Before approving or converting, confirm the applicant’s name, class, session, payment, and result.

### What it does

Students is the main place for student records and changes to a student’s school history.

### Cards on the Students hub

| Assign Teacher | Assign teachers to class sections. |
| Generate ID Cards | Select students and prepare printable ID cards. |

### Common workflow

- Before printing a card or certificate, open the student profile and check spelling, photo, class, and ID.

Student checkout is a history change, not a simple delete. Use it only after the school has confirmed the student’s status.

## 7. Fee Collection

### What it does

Fee Collection manages fee setup, student charges, payments, discounts, and fee reports.

### Cards on the Fee Collection hub

| Card | What it is for |
|---|---|
| Collect Payments | Find a student, review assigned fees, receive payment, and print a receipt. |
| Fee Categories | Create fee types such as tuition, admission, exam, or transport. |
| Fee Sets | Build the fees assigned to a class, session, or group. |
| Scholarships | Manage scholarship information and benefits. |
| Free Studentship | Record students who receive free or reduced fees. |
| Transport Fees | Manage transport-related fee information. |
| Student Payment Report | Review payments by student and fee category. |
| Student Receive Report | Review money received month by month. |
| Student Receivable Report | Review fees assigned or expected by month. |
| All In One Report | Compare payment, received, and receivable information together. |
| Classwise Due | See outstanding dues by class. |
| Student Due | See fee and inventory dues for students. |
| Student Ledger | See a student’s month-by-month fee and inventory history. |
| Discount List | Review discounts recorded for students. |

### How to collect a payment

1. Open Collect Payments.
2. Search for the student using the available student information.
3. Confirm the student name, ID, session, class, and outstanding items.
4. Select the fees the student is paying.
5. Enter the amount, payment date, payment method, and reference if requested.
6. Review the total, discount, and remaining due.
7. Save the payment.
8. Print or download the receipt and give it to the payer.

Never choose another student just because the names look similar. Check the student ID. Do not change or delete a paid record to fix a mistake without first checking the receipt and accounting effect.

### Which report should I use?

- **Student Payment Report:** what a student has paid.
- **Student Receive Report:** money received over selected months.
- **Student Receivable Report:** fees that were assigned or expected.
- **Classwise Due:** unpaid amounts grouped by class.
- **Student Due:** one student’s outstanding fee and stock-related amount.
- **Student Ledger:** the month-by-month history of charges, payments, and balance.

# Part II — Detailed CRUD Guide and Report Guide

## 21. What CRUD means

CRUD is a short name for the four basic actions used in most management pages:

- **Create:** add a new record.
- **Read:** view, search, filter, or open a record.
- **Update:** change an existing record.
- **Delete:** remove a record.

### How CRUD normally looks on a page

1. The list page shows saved records. This is **Read**.
2. Click **Add**, **New**, or **Create** to open a blank form. This is the start of **Create**.
3. Complete the required fields and click **Save**, **Store**, or **Submit**.
4. Use the **eye** or record name to view details.
5. Use the **pencil** or **Edit** button to change a record. Click **Update** or **Save Changes**.
6. Use the **trash** or **Delete** button only when the record should truly be removed.
7. Confirm the success message and recheck the list.

### General CRUD rules

- A field marked with an asterisk is normally required.
- If the system shows a validation message, correct that field and submit again.
- Drop-down lists often depend on earlier choices. For example, choose a class before choosing its sections.
- Search and filters do not change data; Save, Update, Delete, Approve, Promote, Checkout, and Post do.
- Delete is not always available. A record used by students, payments, routines, or reports may be protected.
- When a record is important, update it instead of deleting it and creating a replacement. This keeps the history easier to follow.
- After changing a setup record, check one related page or report to make sure the change has the intended effect.

## 22. CRUD details by module

### Academics CRUD

**Sessions:** Create an academic session with its name and status. Read the session list, update its details or active status, and delete only an unused session. The active session is used by many forms, so check it before changing status.

**Classes:** Create a class with its name, status, and display order. Read the class list, update the name/order/status, and delete only an unused class. Changing a class that already has students or fees can affect many pages.

**Sections:** Create a section under the correct class. Read sections by class, update the section name, and delete only an unused section. Always choose the parent class first.

**Groups:** Create student groups, view the group list, update group names/details, and delete unused groups. Check student assignments before deleting.

**Subjects:** Create a subject with its name and relevant settings. Read its details and classwise assignments, update the subject or assignments, and delete only a subject that is not used in marks or reports.

**Class Rooms:** Create a classroom, view the room list, update its name/details, or delete an unused room. Check routines before removing a room.

**Time Schedule:** Create a period or other time block with name, type, start time, end time, order, and active status. Read and arrange the schedule, update times or status, and delete only a schedule not used by a routine. Overlapping times should be corrected before saving.

**Class Routine:** Create a routine by selecting session/class/section, day, subject, teacher, classroom, and teaching period. Read the routine by class or day, update an entry, and delete an incorrect entry. The system checks conflicts such as the same teacher, room, or section being used at the same time.

### Admission CRUD

**Admission Exams:** Create an exam with session, date, form fee, venue, reporting time, instructions, and classwise total/pass marks. Read its application counts and details, update exam settings, and delete only an exam with no applications. An active exam is normally the exam used for current applications.

**Applications:** Read and search submitted applications, open an application to review details, payment, documents, and status. Applications are normally progressed through review, payment, result, approval, and conversion rather than deleted.

**Admission Payments:** Record or verify the application payment, update its status when authorized, and inspect the related receipt/accounting record. Do not create a second payment for an already-paid application.

**Admit Cards:** Read eligible applicants, generate cards, and print them. Correct the application first if the name, class, photo, or exam is wrong.

**Admission Marks:** Create or update marks for paid applicants in the selected exam and class. Read passed or failed lists and delete/reset a mark only to correct an entry. The result status is calculated from the marks and configured pass mark.

**Approved and Converted Students:** Read approved applicants, use the admission action to create the student record once, then read the converted list. Conversion should not be repeated for the same applicant.

### Students CRUD

**Student records:** Create a student with identity, guardian, contact, address, photo, and academic information. Read the student list/profile, update incorrect details, and avoid deleting a student who has payments, marks, attendance, or history.

**Teacher assignments:** Create an assignment between a teacher and section, read current assignments, update by changing the assignment, and delete an assignment when responsibility changes.

**ID cards and certificates:** These are generated documents rather than ordinary data records. Update the student or institute settings first, then generate the document again.

**Promotion:** This is a controlled update to academic information. Select the source session/class, review students, choose promote or retain, and confirm. Recheck the new session/class afterward.

**Mid-Year Correction:** Select the student and correct the class or section within the same session. Read the student history afterward to confirm that the change did not create an unwanted new session record.

**Checkout:** Record the checkout reason and date. The student remains available in the checked-out list and history. Use the correction or authorized reversal process if the wrong student was checked out; do not create a duplicate student.

### Results CRUD

**Exams:** Create, read, update, and delete exams from All Exams. An exam may also have marks, previews, terminal results, and imported/exported marks. Check those dependencies before deletion.

**Marks:** Create or update marks in the marks-entry screen or student-wise screen. CSV export creates a file for review; CSV import updates marks after the file is checked. Save only the correct exam, subject, class, and session.

**Subject Assignment:** Create assignments for individual students or in bulk, read the assigned subjects, update the selection, and remove an assignment only when the student should not take that subject.

**Report templates:** Template settings are updated through their settings page. They change the appearance or included information of the related report; they do not replace the marks or student data.

### Attendance CRUD

**Daily attendance:** Create attendance for a selected date/class/section, read saved attendance, and update it when a status was entered incorrectly. There is no reason to create a second attendance sheet for the same class and date.

**Attendance settings:** Create a holiday, read the holiday list, and delete a holiday if it was entered by mistake. Weekend and holiday settings affect monthly totals, so check reports after changing them.

### Fee Collection CRUD

**Fee Categories:** Create, read, update, and delete fee categories. A category used in fee sets, fees, or reports should usually be renamed or deactivated rather than deleted.

**Fee Sets:** Create a set by choosing the correct session/class/group and adding fee items, amounts, frequency, and applicable dates. Read the set and assigned items, update before assignment when possible, and delete only an unused set. Confirm the student ownership when using an individual fee.

**Assigned Fees:** Fee assignment creates the amount a student is expected to pay. Read the assigned fee lines, update only through the fee-management action, and do not delete a paid line to hide a balance.

**Payments:** Create a payment by selecting the student and fee lines, read the receipt/payment detail, update only an authorized correction, and delete or reverse only through the approved payment process. The payment date is the business date used in payment reporting; the created date is the system audit time.

**Scholarships, Free Studentship, and Transport Fees:** Create the benefit or transport record, read it on the student or list page, update the effective amount/date, and remove only an incorrect or unused record. Recheck the student due and ledger reports after a change.

### Accounts and Financials CRUD

**Account Groups and Chart of Accounts:** Create the group first, then create an account inside it. Read and update names or links carefully. Delete only unused groups/accounts; used accounts should be preserved for historical reports.

**Accounting Periods:** Create a period with start and end dates, read its status, and close/lock it when the books are final. A closed period should not be edited or deleted.

**Income and Expense Categories:** Create categories before recording transactions. Read and update labels when necessary; delete only unused categories.

**Incomes and Expenses:** Create a record with date, category, amount, payment account/method, reference, and description. Read it in the list and Accounts reports, update authorized corrections, and delete only when the source transaction is wrong and the accounting impact has been checked.

**Capital:** Create a capital entry through the shareholder transaction page, read it in Financials and Accounts, update only with supporting evidence, and delete only through an approved correction.

**Journal Entries:** Create a balanced entry with at least one debit and one credit, read its reference and lines, update only while allowed by the accounting period, and delete only when the related accounting records are understood. The total debit must equal total credit.

**Bank Accounts, Mobile Banking, and Hand Cash:** Create an account/register, read its balance and movements, update its name/details, and delete only an unused account. Transfers should be recorded using the provided transfer action so both sides remain understandable.

### Inventory CRUD

**Categories, Products, and Suppliers:** Create the category, then the product and supplier. Read lists and search/filter them, update names, prices, minimum stock, and contact information, and delete only unused records.

**Purchases:** Create a purchase with supplier, date, products, quantities, and cost. Read the purchase and its items, update an incorrect purchase where permitted, and delete only after checking stock and accounting effects.

**Opening Stock:** Create opening quantities and average cost once when starting the system. Read the resulting product stock; correct it through the opening-stock or product process rather than entering the same stock again.

**Sales:** Create a sale through the Sales Hub, read it by receipt, student, product, purchase source, or date, and use the available correction process if wrong. Sales are linked with payment and stock, so do not delete a sale casually.

### HR, Assets, Institute, Locations, Users, and Communications CRUD

- **Employees:** Create, view, update, and delete an employee record only after checking salary, leave, documents, and payment information.
- **Departments and Designations:** Create setup values, read lists, update names, and delete only values not used by employees.
- **Leave Requests:** Create or receive a request, read its status, update the decision or details, and delete only an accidental request.
- **Assets:** Create categories and asset records, record purchases, issue/return assets, read stock/location history, and correct the source record rather than removing a traceable asset.
- **Facility Bookings:** Create a booking with facility, date, time, and requester; read the calendar/list; update or delete a cancelled booking.
- **School Settings, Certificates, Buildings, and Rooms:** Create or update setup records, read the saved settings, and remove only unused buildings/rooms or obsolete templates.
- **Divisions, Districts, Police Stations, and Post Offices:** Create parent locations first, read dependent lists, update spelling/details, and delete only unused locations.
- **Users:** Create a user, assign a role, read the user list, update status/role/contact details, and deactivate or delete only after checking ownership of their work.
- **Roles and Permissions:** Create a role, assign permissions, read the permission summary, update access, and delete only an unused role.
- **Communications:** Create a conversation, read messages, edit or delete an allowed message, and upload an image only when needed. A conversation is not the same as a student or accounting record.

## 23. How to use filters and exports

1. Select the filters before clicking Filter, Search, Go, or Load.
2. Use the exact date format shown beside the field, commonly `dd/mm/yyyy`.
3. For fee reports, choose the correct session/class/section and category options before loading.
4. For result reports, select the session first, then exam type/exam and class or section as requested.
5. Check the on-screen totals before clicking PDF, Print, Export, or Send Email.
6. A PDF uses the filters currently selected. If the PDF looks wrong, return to the screen and confirm the filters before printing again.

## 25. Report reading rules

- **Total:** the sum of the rows currently included by the filters.
- **Paid/received:** money already recorded as collected.
- **Assigned/receivable:** money expected or charged, whether or not it has been paid.
- **Due/balance:** the remaining amount after the system’s assigned and paid values are compared.
- **Debit and credit:** the two sides of an accounting entry; they should balance at the trial-balance level.
- **Opening/beginning balance:** the amount carried into the selected period.
- **Period movement:** activity inside the selected dates.
- **Ending balance:** opening balance after the selected period’s movements.
- **PDF:** a printable copy of the currently selected report; it is not a new record.

## 26. Safe correction procedure

When a report looks wrong:

1. Check the report filters and date format.
2. Open the underlying student, payment, attendance, inventory, or accounting record.
3. Correct the source record in its own module.
4. Reload the report.
5. Compare the old and new totals.
6. If money, student history, or a posted journal entry is involved, ask the authorized administrator/accountant before deleting anything.

Never fix a report by changing only the display or by creating an opposite entry without understanding the original entry. The report is calculated from the saved source records.
